# iPhone 与 Mac 局域网同步

## 前提

- 同一局域网，允许设备之间通信；两台App均打开并可响应。不要求两端使用相同Apple账号
- 主App与Widget仍需正确Apple签名和App Group能力，局域网同步不需要iCloud容器
- 首次实际使用时允许系统局域网访问；Mac沙箱配置包含network.client/network.server
- 两端只与用户明确配对的对方交换内容，不通过开发者服务器或云服务

## 首次配对

1. 在两端打开“局域网同步”并开启局域网连接，再在一端创建随机128bit配对码
2. 在另一端输入这份32个十六进制字符的配对码（界面可分组显示）
3. 两端核对同一组6位会话数字，再分别确认；设备名称本身不作为信任依据
4. 确认前只完成必要握手，不传待办/笔记等用户记录
5. 系统TLS使用PSK认证与加密；配对秘密保存在设备专用Keychain，不进整包备份，不记录到日志

配对码只给你身边自己的另一台设备，不要发送到助手聊天、公开截图或告诉其他人。复制使用本机限定、短时剪贴板，避免主动放入跨设备通用剪贴板。

本版为一对iPhone/Mac设计，不是多用户分享或任意设备文件服务器。配对可取消；解除配对只解除信任，不删除用户记录。

## 日常同步

任一端点击同步，交换两端受限的逐条因果记录；新增、修改、完成和删除都参与合并。只有对方提交到本地并确认的批次才可报告已确认；断线、部分交换或后来新修改仍显示待同步，不能把“发出”当成“另一台已保存”。

两端离线可继续编辑。并发修改保留完整冲突版本；一端删除、另一端编辑时也保留冲突供审阅，不按文件时间覆盖整库。

另一端关闭、挂起或被网络隔离时不会被强制唤醒。请重新打开两端、核对局域网权限后重试。不要为排障开放公网端口、关闭整个防火墙或降级为明文。

## 提醒边界

每台设备各自安排本地通知，系统授权不跨端。两端都授权时可能各自响。

一端完成/删除后，离线或暂停的另一端已排提醒不能即时撤销；它接收同步并重排之后才更新。Widget同设备勾选会持久化后立即尝试撤销/重排本机提醒，无需先打开主App。跨设备传递仍要等主App参与局域网交换，不能把本机勾选说成另一端已收到。

## 必须实际验证

源码未在Xcode/真机/真实网络运行。交付静态通过不能替代以下验收：

- iPhone↔Mac发现、首配正确码/错误码、双方确认/任一端拒绝、取消与反复进入
- 错码/未配对/仅单边确认时没有用户内容传输
- TLS失败没有明文fallback；握手/帧大小/解码失败明确终止
- 任端点击同步，另一端真实提交后ACK；拔网/切后台/对方退出时不报假成功
- 两端离线改同记录、删除与编辑并发、双端完成重复任务、时间戳差异不伪造业务冲突
- 交换中继续编辑不被旧ACK清掉新pending；重试幂等
- 备份导入先暂停传播，明确合并后不将缺项当删除；秘密与配对信任不进备份
- 解除配对、旧端重装、设备身份不匹配必须重新核对
- 手机Widget完成/提醒撤销、Mac改动同步至手机并刷新、两端通知规则一致

实际签名、Apple账号能力和App Group不是本地源码工具可代你完成的；不提供虚假IPA或“永久免签”承诺。
